# 舊網址轉址頁：上傳說明

這個資料夾是 repo 移轉（`linkmasterking/-` → `STUSTSA/council`）後，給舊網址 `https://linkmasterking.github.io/-/` 用的轉址頁。
它們**不在看板網站生效**：放在看板 repo 裡只是保管，要上傳到你個人帳號的 `linkmasterking/linkmasterking.github.io` repo 才會作用。

## 什麼時候做

移轉當天，在 GitHub 上完成 Transfer ownership、確認新網址 `https://stustsa.github.io/council/` 打得開**之後**
（`docs/architecture/github-ownership-migration.md` 第 1.4 節 S5）。
移轉前不要上傳：舊網址那時還由看板 repo 提供，轉址頁不會被看到。

## 要上傳的檔案（共 5 個）

| 這個資料夾裡的檔案 | 上傳到 `linkmasterking.github.io` repo 的位置 | 作用 |
|---|---|---|
| `-/index.html` | `-/index.html` | 打開 `/-/`、`/-/?d=…` 時轉到新網址 |
| `-/home.html` | `-/home.html` | 打開 `/-/home.html`（已安裝的 App 從這裡開）時轉到新網址 |
| `-/sw.js` | `-/sw.js` | 取代舊看板的離線 Service Worker：刪掉舊快取、解除註冊 |
| `-/manifest.webmanifest` | `-/manifest.webmanifest` | 已安裝的 App 打開時顯示「已搬家」 |
| `404.html` | **根目錄** `404.html` | `/-/` 底下其他網址（例如 `/-/core/board.css`、舊的分享連結）也轉到新網址 |

- `404.html` 一定要放在**根目錄**，不是 `-/` 裡面：GitHub Pages 只認網站根目錄的 `404.html`。
- `上傳說明.md`（這份）**不要**上傳。
- 三個 HTML 檔內容完全相同，不用改任何字。

## 步驟（在 GitHub 網頁上，約 10 分鐘）

1. 登入**你的個人帳號** `linkmasterking`。
2. 確認 `https://github.com/linkmasterking/linkmasterking.github.io` 存不存在：
   - **不存在**：右上「＋」→ New repository → Repository name 填 `linkmasterking.github.io`（全小寫、一字不差）→ Public → Create repository。
   - **已經存在**：先看根目錄有沒有 `404.html`。有的話先停下來告訴我，那個檔案要合併，不能直接蓋掉。
3. **不要**在個人帳號建立名叫 `-` 的 repo（會讓 GitHub 對舊 repo 位置的自動轉址失效，所有人的 git 連結與舊 PR 連結都會斷）。
4. 上傳根目錄的 `404.html`：repo 首頁 → Add file → Upload files → 拖進 `404.html` → Commit changes。
5. 上傳 `-/` 底下 4 個檔案：Add file → Create new file → 檔名欄打 `-/index.html`（打出 `/` 會自動變成資料夾）→ 內容貼上 `-/index.html` 的全文 → Commit changes。
   `-/home.html`、`-/sw.js`、`-/manifest.webmanifest` 用同樣方式各建一次。
   （也可以先在電腦上建一個叫 `-` 的資料夾放這 4 個檔，用 Upload files 整個資料夾拖進去。）
6. repo 的 Settings → Pages：Source 選「Deploy from a branch」，Branch 選 `main`、資料夾 `/ (root)` → Save。
7. 等 1～2 分鐘，Actions 分頁的部署變成綠勾。

## 上傳後檢查（手機、電腦各一次）

| 打開這個網址 | 應該到 |
|---|---|
| `https://linkmasterking.github.io/-/` | `https://stustsa.github.io/council/` |
| `https://linkmasterking.github.io/-/home.html` | `https://stustsa.github.io/council/home.html` |
| `https://linkmasterking.github.io/-/index.html?d=events` | `https://stustsa.github.io/council/index.html?d=events`（活動部） |
| `https://linkmasterking.github.io/-/?d=fruit#join=測試` | `https://stustsa.github.io/council/?d=fruit#join=測試` |

- 已經把舊看板加入主畫面的手機：打開舊圖示，應該被帶到新網址；之後刪掉舊圖示、在新網址重新加入主畫面。
- 如果打開舊網址還是看到舊看板：那是舊的離線備份，連上網路重新整理一次就會換成轉址頁。

## 這些檔案做什麼、不做什麼

- 只做導向：保留網址後段、`?` 查詢字串與 `#` 片段，用 `location.replace` 轉到新網址；瀏覽器關掉 JavaScript 時轉到新首頁。
- 不收集、不送出任何資料，不讀寫這台裝置的瀏覽器儲存區（舊網址裡留著的權杖、草稿都不碰）。
- `sw.js` 只刪舊看板自己的快取（名稱 `board-cache-` 開頭），同一個網域底下的其他網站不受影響。
- App 圖示直接用新網址的圖片，所以要在新網址上線後才上傳。
- 建議永久保留（免費、不用維護），最少保留到 2027 學年結束。
- 測試：`tools/tests/rd1.js`（用模擬網域檢查上面四個網址與清除快取）。
