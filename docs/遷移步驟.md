# 第一次工作：把 repo 從「免資料夾版本」換成有資料夾的原始碼

給 Claude Code 照做。做之前先讀根目錄的 `CLAUDE.md`。這一次只做搬家，不改任何功能。

## 背景
- 以前用 GitHub 網頁上傳，不能傳資料夾，所以 repo 根目錄放的是攤平後的檔案：`core-xxx.js`、`core-board.css`、`dept-xxx.png`、`dept-config.js` 等，`index.html`、`home.html`、`manifest.webmanifest`、`sw.js` 裡的路徑也被改寫成這些檔名。
- 使用者已把 `工作看板-遷移包-1105q.zip` 上傳到 repo 根目錄。裡面是有資料夾的原始碼（`core/`、`dept/`、`index.html` 等）、`CLAUDE.md`、`docs/`、`tools/tests/`、`assets/`、`.gitignore`。**裡面沒有任何 `data*.json`。**

## 步驟
1. 開新分支 `migrate-to-folders`。
2. 先列出 repo 根目錄所有檔案，分成三類回報給使用者：
   - 資料：`data.json`、`data-*.json`、`archive/` → 完全不動。
   - 舊的攤平檔：`core-*.js`、`core-board.css`、`dept-*`（`dept-config.js`、`dept-*.png`、`dept-favicon.svg`、`dept-cover.png`）→ 第 5 步刪掉。
   - 其他看不出用途的檔案 → **先問使用者**，不要自己刪。
3. 把 zip 解壓到根目錄（會新增資料夾、覆蓋 `index.html`、`home.html`、`manifest.webmanifest`、`sw.js`）。
4. **保留分享預覽的文字**：使用者可能用看板的「分享預覽」改過線上 `index.html` 的 `<title>`、description、`og:*`、`twitter:*`。解壓前先記下舊 `index.html` 的這些值；如果跟新版不同，把舊的文字寫回新版。但圖片網址要用新路徑 `…/dept/cover.png`（舊版是 `…/dept-cover.png`，那個檔第 5 步會刪掉，留著的話連結預覽會沒有圖）。`home.html` 一樣檢查。
5. 刪除舊的攤平檔，以及上傳的 zip 本身。
6. 檢查：全 repo 搜尋 `core-`、`dept-` 這類舊檔名，確認沒有網頁還在引用；`node --check` 檢查所有 `core/js/*.js`。
7. 跑測試（方法見 `CLAUDE.md`）：`v2.js`、`lv1.js`、`se1.js`、`sp1.js`、`bk1.js`。`mt1.js`、`sch1.js` 在搬家前就已知會壞（見交接說明二十七節），不用修，回報即可。另外用瀏覽器實際開 `index.html`、`index.html?d=finance`、`home.html`，確認沒有 404 與 console 錯誤。
8. 在 `docs/交接說明.md` 加一節「三十一、改用 Claude Code」：repo 已改成有資料夾的結構、不再用 zip 與 flat.py、交付改成分支＋PR（細節見 CLAUDE.md）、這次搬家刪了哪些檔、分享預覽文字有沒有搬過來。開頭那行「程式碼在交接包.zip…」改成「程式碼就在這個 repo」。
9. 發 pull request，說明裡列出：新增／刪除的檔案、保留了哪些分享預覽文字、測試結果。

## 請使用者合併後檢查
- 手機、電腦各開一次看板與總覽頁；換一個部門（`?d=finance`）。
- 進「編輯」改一個小地方、儲存並同步，確認存得進去（這會寫 `data.json`，代表權杖與同步正常）。
- 已經安裝成 App 的手機：關掉重開一次（Service Worker 是網路優先，重開就會拿到新檔）。
- 出問題：在 GitHub 上把這個 PR revert，網站會回到搬家前。
