# 學生會工作看板（權益部起家）：交接說明（2026-11-05 更新；最新進度見三十一、三十二）

新對話開始時先讀這份，再讀同一個專案裡的 `DESIGN.md`。程式碼就在這個 repo（`linkmasterking/-`，根目錄就是網站），交付方式見根目錄 `CLAUDE.md`。

## 一、這是什麼
- 南臺科大學生會權益部的工作看板，屬於專案「南臺共榮圈數位革新」（把可線上化的行政程序工具化、簡化）。
- 網址 https://linkmasterking.github.io/-/ ，GitHub repo `linkmasterking/-`（分支 main）。
- 純前端，放在 GitHub Pages；資料在 repo 的 `data.json`，透過 GitHub Contents API 讀寫同步。
- 使用者是權益部幹部，用繁體中文溝通。

## 三、現行功能
- **頁首**：部門 logo、學年、開學第幾週、看板名稱、大日期；儲存資訊；按鈕列「編輯｜每週概述」，編輯中換成「取消｜儲存並同步｜每週概述」（手機也同一列）。
- **底部常駐工具列（桌面 900px 以上是左側細欄，只有圖示）**：毛玻璃 `.glass`、實心鏡片（見第二十二節）；按鈕機制照 Convx，手機與桌面同一套（見第二十一、二十二節）；分頁「即時回報｜進度｜完成紀錄」加獨立設定鍵；鏡片可拖曳（滑鼠、觸控都行）；文字依背後顏色自動反轉；設定打開時三個分頁都不亮，點任一個就關掉回到那一區。
- **區塊**：手機一次只顯示一區（預設即時回報），切換時淡出淡入；桌面全部顯示，選到的區塊放大到最上面、其他兩區排在下面（FLIP 動畫）。
- **即時回報**：膠囊整塊依狀態上色（綠＝期限前有更新、白＝這週完成過一段或期限後才補更新、紅＝期限前後都沒更新；期限是 `dept/config.js` 的 `week.cutoff`，預設週二）。可連到一個母議題。
  - 編輯分兩段：「+ 新增即時回報」只填名稱、說明、專員；展開後的工具列有「與議題連結｜+ 超連結｜+ 時間｜編輯｜完成這一段｜結案」。
  - **版面長度過渡**（2026-11-05）：`motion.js` 末段 `flowWatch`／ResizeObserver。`.panel`、設定頁 `.set-list`／`.set-pane` 高度一變就從舊高度滑到新高度；寬度同時變（換區塊、縮放）、第一次出現、裡面膠囊正在展開收合（`_busy`）、減少動態時不做。新增會變高的容器不用另外寫動畫，只要符合 `FLOW_SEL`。
- **完成紀錄**（2026-11-05）：跟即時回報同一套膠囊（`.ev.done-ev`、`data-st="done"`、`data-done=id`）與左右兩欄；收合時空心綠框綠字。舊的 `.done-item` 清單樣式已刪除。
- 「匯出定型版」已移除（含 `bundleTemplate`）；只剩匯出／匯入備份。
- 工作報告第一頁標題下有「查看看板即時動態」連結（`report.js` 的 `boardURL()`，網址照印）。
- **會議要報告**（2026-11-05）：編輯中展開即時回報（或桌面右側詳情）按「會議要報告」標記，存在 `events[].report`（schemaVersion 7）；膠囊與詳情標題顯示紅框「報告」小標。已標記的排在上方「會議報告事項」區、其他在下方「其他回報」區（沒有報告事項時只有一區）；標記或取消時膠囊 FLIP 移過去；上一個／下一個照畫面順序（`views.js` 的 `liveOrder`）。按「生成週報」後所有標記自動清掉（手動新增週報不清）。標記不算「更新」，不影響燈號。
  - **時間標記**：名稱＋日期，可加時刻、可加結束（變成期間，自動算天數或時數）；可勾「也寫進母議題的處理紀錄」（預設不勾）。
  - **完成這一段**：填「這段完成了什麼」與「下一段要追什麼」，在完成紀錄新增一筆「名稱（第 N 段）」，卡片留著、段數加一；已經過去的時間標記跟著這一段移走，未來的留在卡片上。可以無限延續。
  - **結案**：整筆移到完成紀錄（分過段的顯示「第 N 段・結案」），有母議題就寫一筆處理紀錄。
  - 加時間、改內容、加連結、完成一段、連結議題都算「更新」，只是展開收合不算。
- **進度卡片**（2026-11-05 起甘特圖與個別進度合成一張）：預設顯示甘特圖（未排程的議題也列在最下面、沒有條）；點議題列，甘特圖往下淡出、該議題詳情往上淡入；「返回甘特圖」切回來（`views.js` 的 `progShow`／`renderCards`，狀態 `progOpen`）。「+ 新增議題」在甘特圖下方，新增後直接進詳情。處理紀錄不再有編輯鈕（改註記一律點時程條上的標記）。詳情內容（議題卡片：階段標籤、時程、註記〔在時程條上按住拖曳新增，位置＝日期〕、處理紀錄、連結、專員）。
- **時程**：議題的期間（開始日～結束日）到今天已經過的比例（`util.js` 的 `schedPct`），甘特圖與卡片的條一律照時程填綠；沒有期間顯示「未排程」。手動完成度已拿掉；完成改成編輯中卡片工具列的「結案」（`doneAt` 有值＝已結案，儲存後移到完成紀錄；完成紀錄裡可「取消結案」）。
- **左右兩欄**：桌面 1000px 以上、「即時回報」或「完成紀錄」被選到時（進度改用上面的甘特圖／詳情切換），該區改成左清單右詳情（`render.js` 的 `mdOn`、`selEv`／`selDone`）。即時回報的右側詳情編輯中可直接改所有欄位（`views.js` 的 `evDetailHTML`、`events.js` 的「右側詳情（編輯中）」段），手機與總覽仍是展開膠囊＋對話框。
- **完成紀錄**：反白區、綠燈；放大時用多欄。
- **每週概述**：右滑頁；生成週報只列「會議報告事項」（沒人標時改列全部即時回報）與「本週完成」兩區的標題（見三十二）。
- **編輯模式**：頁首「編輯」只負責登入、進入編輯狀態與最後的「儲存並同步」「取消」；看板上各區（即時回報、進度、完成紀錄、會長室的追蹤）要再按標題列的「編輯這區」才出現編輯工具，一次只能開一區（見第二十七節）。週報頁照舊跟著頁首「編輯」。刪除鍵在該區編輯中直接顯示（即時回報膠囊上的 ×、卡片工具列、完成紀錄與週報的摘要列），都會先確認。
- **設定頁**（登入前整頁只顯示鎖頭與登入鈕；桌面 900px 以上點了有下一層的項目，清單左滑、右側面板顯示內容，細節見 DESIGN.md）：
  - 紀錄：編輯紀錄（讀 GitHub commits）
  - 人員與權限：身分與專員
  - 看板資訊：名稱、看板日期、學年、開學日（每項單獨改）
  - 雲端與分享：雲端同步、分享預覽（改 repo 裡 index.html 的 og 標籤）
  - 匯出與備份：匯出定型版（單一 HTML、拿掉密碼雜湊與加密權杖）、匯出備份（JSON）、匯入備份、匯出工作報告
  - 這台裝置：忘記這台裝置
  - 安裝成 App 說明
  - 沒在編輯時改設定會直接儲存並同步；編輯中改的併入這次編輯，按儲存才上傳。
  - 程式：`nav.js` 的「設定頁：桌面版右側面板」（`paneRun`／`paneDismiss`／`setPaneHost`）；對話框一律經 `dialog.js` 的 `dlgOpen(modal)` 打開，由它決定畫在面板裡還是跳出；`teamSettings()`、`openLog()` 會回傳在關閉時完成的 Promise。
- **登入**：選身分＋個人密碼（至少 12 碼）。舊看板（沒有身分）先用部門共用密碼，再建立第一位管理員。同一次開著網頁只要登入一次。可勾「在這個裝置上記住密碼」：localStorage 只存身分 id 和密碼雜湊的指紋，不存密碼、不上傳；密碼一改就失效；設定頁可「忘記這台裝置」。
- **每週概述紅點**：每週五起、這一週（週一到週日）還沒有週報就亮，產出後消失；沒產出會一直亮（`weekly.js` 的 `weekDue`）。
- **工作報告**（設定頁 → 匯出工作報告）：選起訖（預設本學期開學日到今天）→ 白紙預覽（字都能直接改、可新增或移除區塊、標題自動編號）→「存成 PDF」用瀏覽器列印另存。內容：本期摘要（四格數字＋期間甘特圖）、議題處理情形（逐案）、工作檢討、下期規劃。A4、頁尾頁碼、空白區塊不印。預覽打的字不存進看板。
- **PWA**：`manifest.webmanifest` 的 display 是 fullscreen（安卓安裝版藏起狀態列與導覽列，解決底部黑條）；`sw.js` 網路優先，`data.json` 不快取；斷線時顯示「離線中」並改唯讀。

## 五、資料（data.json，schemaVersion 8；v7→v8 見三十二）
- 看板：`title`、`yearLabel`、`termStart`、`range{start,end}`、`savedAt`、`savedBy`、`locked`、`labels[]`（人事時地物標籤 `{id,kind,name}`）；`boardDate` 已拿掉（v8），大日期＝`savedAt`
- `issues[]`：`{id,title,tags[],cur,start,end,doneAt,note,markers[{id,at,date,stage,text,pos,evId,tmId}],links[{id,name,url,color}],staff[],labels[]}`（`staff` 存 member id，`labels` 存標籤 id）；`doneAt`＝結案日（null＝進行中）。有期間的議題，註記位置以 `date` 為準（`at` 只在沒有期間時用）
- `events[]`（即時回報）：`{id,name,desc,createdAt,doneAt,issueId,links[],staff[],labels[],times[],round,roundAt,touched[],touchedAt,fromEv,report}`
  - `times[]`：`{id,label,start,end,place,toIssue}`（`place` 地點，自由文字，可空白），`start`／`end` 是 `2026-11-04` 或 `2026-11-04T14:00`，`end` 空的就是單一時間點
  - `round` 目前第幾段；`roundAt` 上次完成一段的時刻；`touched` 最近幾次更新的日期（最多 8 個，判斷狀態用）；`touchedAt` 最後更新時刻
  - 「完成這一段」產生的紀錄也放在 `events[]`，帶 `fromEv`（來源卡片 id）與 `round`，`doneAt` 有值，所以完成紀錄、動畫、週報、工作報告都會自動讀到；它不算「新增的即時回報」
  - 母議題的處理紀錄（`markers`）由即時回報寫入的帶 `evId`；由時間標記寫入的再多 `tmId`
- `weeks[]`：`{id,date,text,auto}`；`reportBase{date,issues{id:{stage,note}}}` 是上一份週報當時的快照
- `members[]`：`{id,name,role:"admin"|"member",kdf,tok,createdAt}`（也是卡片上可以標的「專員」）；`staff[]` 名單已拿掉（v8）
- `pwKdf`（共用密碼雜湊）、`sync{owner,repo,branch,path,tokenEnc}`
- v5 → v6：拿掉 `issues[].progress`；原本 100% 的視為已結案（沒有結案日就用 savedAt）；有期間的議題，沒有日期的註記依原本的 % 換算出日期。
- v4 → v5：舊的即時回報當作在最近一次回報期限當天更新過（上線時顯示綠色）。
- 改結構一定要加 schemaVersion 和自動遷移（`state.js` 的 migrations），舊的 data.json 要能直接讀。

## 六、同步與安全
- 權杖：Fine-grained、只限這個 repo、Contents 讀寫。存在裝置的 localStorage；另外用個人密碼 AES-GCM 加密存進 `members[].tok`、用共用密碼加密存進 `sync.tokenEnc`，所以別的裝置輸入密碼就能自動連上。
- 密碼雜湊：PBKDF2-SHA256、210000 次。
- 同時修改：用 sha／ETag，409／422 擋下後存的人。commit 訊息「〔名字〕類別｜內容」＋明細＋`Board-Log: 1`，編輯紀錄頁讀這些 commit。
- **絕對不要在對話中要權杖，程式也不能把權杖印到畫面或 console。** 曾在聊天中貼出的權杖要作廢重產。

## 七、測試
- 本機用 `python3 -m http.server` 開原始碼（另放一份 `data.json`），用 Playwright（Chromium）跑；GitHub API 用 route 模擬（GET 回內容、PUT 更新 sha、`/commits` 回清單）。
- 交接包的 `工具/測試/`：
  - `v2.js`：分頁、版面、設定、登入、刪除鍵、記住密碼、手機觸控拖曳
  - `v2b.js`：身分與專員、匯出匯入、週報與議題刪除、唯讀、減少動態、忘記裝置
  - `rp1.js`：工作報告流程＋輸出 PDF
  - `cs.js`：自製下拉選單
  - `sch1.js`：結案按鈕、時程條上拖曳新增註記（標籤顯示日期、對話框沒有 %）、儲存後移到完成紀錄、schemaVersion 6
  - `lv1.js`：即時回報桌面左右兩欄（選取、編輯中直接改名稱／說明／母議題／時間／連結、完成這一段、儲存）、手機不分欄
  - `sp1.js`：設定頁鎖頭、登入、桌面左右兩欄（切換、Esc、再點收起）、手機跳出
  - `lg1.js`：手機工具列（深淺色：靜止、按住鏡片、拖曳、放開、點分頁中途、設定鍵按壓的截圖與數值）
  - `lg2.js`：工具列（桌面細欄深／淺、手機）：按住鏡片放大、拖曳、放開切換、點分頁中途、設定鍵；印出鏡片位置與反白的分頁
  - `se1.js`：分區編輯（只有「編輯這區」→ 開一區 → 開另一區時前一區自動收起 → 收起 → 取消 → 再進入時全關；桌面 1300、手機 412；固定 8300 埠）
  - `ev1.js`：即時回報狀態顏色、時間標記、完成這一段、結案、深色與手機（用 `data_v5.json`）
- 交付前給使用者預覽：把 CSS／JS 內嵌成單一 HTML、放入資料、拿掉 `sync`（不連 GitHub），用檔案卡片傳。

## 十一、什麼時候請使用者開新對話
長對話會自動壓縮（把前面的內容摘要），細節會掉、每則訊息的用量也越來越大。所以由 Claude 主動提醒，不要等使用者發現。

**出現下面任一情況，在那一輪回報的最後一行提醒「建議開新對話」：**
1. 一批相關的修改做完、交付了（例如「即時回報這輪改完」「多部門上線」），下一個要求是不同區塊或不同主題。
2. 這個對話已經交付約 5 包（看檔名的流水號），或來回超過約 20 輪。
3. 發現自己忘了前面做過的事：較早的工具輸出已被清掉、要回頭翻檔案才知道現況、或做出跟前面決定矛盾的東西。
4. 同一個區塊在這個對話改超過三次（本來就要提醒整理），而且接下來要做的是整理或大改。
5. 接下來要做結構性的大改（改資料結構、拆檔、拆 repo、新增部門類型），先在乾淨的對話裡做比較安全。

**提醒時一起做好：**
- 把本次對話的決定寫進這份交接說明（功能、資料欄位、待辦），設計規則寫進 `DESIGN.md`。
- 打包新的交接包（檔名帶日期流水號），連同 `交接說明.md`、`DESIGN.md` 一起給使用者。
- 告訴使用者三件事：換掉專案裡的舊 `交接說明.md`、`DESIGN.md`；新對話上傳最新交接包；開頭說「先讀交接說明和 DESIGN.md」。

**不要因為這些情況就提醒：** 只是小修（對齊、顏色、文字）、使用者正在連續微調同一個畫面的手感。等那一串調完再提醒。

## 十九、做法與判斷原則（2026-11-04 對話整理）
- **新增功能前一定先問，不要先做。** 使用者說「寫進交接」就是只寫文件；說「直接做」才做。曾經在使用者回「我想要」時直接實作，使用者不希望這樣。
- **一個對話只做一批**，做完出交接包、開新對話；對話太長時前面內容會被截掉，容易出錯。
- 使用者列需求時可能會在每項前標：「錯」＝bug、「定」＝決定要做、「想」＝還在想。只有「錯」和「定」可以排進實作；「想」只討論。沒標的先問。
- 版面類需求請使用者先畫草圖（這次半邊詳情卡就是靠草圖才對齊）；動畫、版面、按鈕少討論多試做，做出來給預覽；會動到資料結構的才事前把問題問完。
- **判斷要不要加功能**：每週會有人用到嗎？需要人照顧的功能，有沒有綁在固定的例行事件上（例如每週行政會議）？有＝流程設計（例：會報勾選），沒有＝容易換屆後沒人管（例：標籤整理、臨時審核）。只是「看」的功能（今日／明日處理、行事曆）學習成本低。
- **可學習性**：部長每週必用的只有新增／更新即時回報、拉議題進度、開會點開來講、生成週報；其他功能不學也不影響。建議交接文件把功能分三級：每週必用／偶爾會用／不用學。容易卡人的：登入與建立身分、「完成這一段」跟「結案」的差別、時間標記。
- **驗證方式**：找一位沒碰過看板的部長做五分鐘測試（例：「新增一筆即時回報，再把它結案」，不幫忙），卡住的地方就是要改的地方。建議節奏：會前做一小批（三到五項）→ 會中實際用、隨手記 → 會後整理清單。
